# RSJP Schedule — Functional Specification

Updated: 2026-08-18

## 1. Purpose

RSJP Schedule is a browser-based scheduling tool for RSJP and custom short-term programmes. It is intended to help staff prepare programme schedules, generate routine Japanese-class entries, manage event details, and export schedules for operational sharing.

This application is an operational support tool. It is not a system of record for student personal data, contracts, payments, attendance, room reservations, transport reservations, or other institutional transactions.

## 2. Supported workflow

1. Create or select a programme.
2. Set programme name, type, student count, start date, and end date.
3. Configure the default Japanese-language class pattern.
4. Apply date-specific Japanese-class overrides when needed.
5. Run automatic schedule generation.
6. Add or edit non-generated events manually.
7. Review the calendar preview.
8. Export JSON for backup and transfer.
9. Export CSV, ICS, or HTML for downstream use.

## 3. Programme types

- RSJP
- Custom

The programme type is descriptive. The current application does not enforce a separate business-rule engine by programme type.

## 4. Schedule categories

- Japanese Class
- Orientation
- Escort
- Campus Tour
- Cultural Experience
- Company Visit
- Buddy Lunch
- Completion Ceremony
- Other

## 5. Automatic generation

Automatic generation replaces only items previously generated by the automatic-generation routine for the selected programme. Manually entered events are retained.

The current generator creates:

- first-day escort
- first-day orientation
- first-day campus tour
- completion ceremony template entry
- Japanese-language classes on weekdays between the programme start and end dates, subject to programme settings and date-specific overrides

Staff must review generated entries before operational use. Generated entries are templates, not confirmed reservations.

## 6. Japanese-class configuration

Programme-level configuration supports:

- enabled / disabled
- start time
- lesson duration
- break duration
- number of periods
- number of classes
- class display names
- default teacher room

A date-specific override can change:

- enabled / disabled
- start time
- lesson duration
- break duration
- number of periods
- number of classes
- classroom list
- teacher-room list

## 8. Export functions

### JSON

JSON is the application backup and transfer format. It contains the programme and schedule state used by the application.

### CSV

CSV provides a tabular schedule suitable for spreadsheet use and downstream operational processing.

### ICS

ICS provides calendar events using Asia/Tokyo as the intended time zone.

### HTML

HTML provides a printable/shareable calendar-style representation.

### Japanese / English output

The application supports Japanese and English export modes. English-specific fields should be entered when accuracy matters. The built-in fallback translation is intentionally limited and must not be treated as professional translation.

## 9. Data storage

Primary runtime storage is browser localStorage using the application storage key.

Consequences:

- data remains on the browser/profile in which it was created
- data is not automatically synchronized between devices
- clearing site/browser data can remove the working dataset
- changing browsers or computers does not transfer data automatically
- the repository and Vercel deployment do not themselves constitute a shared schedule database

JSON export is therefore mandatory as the operational backup method.

## 10. Data classification

Do not enter unnecessary personal information into titles, locations, or notes. In particular, avoid passport data, medical data, immigration documents, personal addresses, private phone numbers, or other sensitive student information.

This application should contain operational schedule information only.

## 11. Human-control principle

The application does not confirm bookings, reserve rooms, appoint staff, place transport orders, or send schedules automatically. Staff remain responsible for checking and approving schedule information before external or institutional use.

## 12. Current limitations

- no user authentication
- no central database
- no multi-user real-time collaboration
- no server-side audit log
- no automatic institutional backup
- no automatic room or transport reservation
- no authoritative translation engine
- no automatic conflict resolution

These limitations are acceptable only when the application is used according to the operational rules in `OPERATIONS.md`.
