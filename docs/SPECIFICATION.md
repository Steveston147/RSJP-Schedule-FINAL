# RSJP Schedule — Functional Specification

Updated: 2026-08-23

## 1. Purpose

RSJP Schedule is a browser-based scheduling tool for RSJP and custom short-term programmes. It is intended to help staff prepare programme schedules, generate routine Japanese-class entries, manage event details, and export schedules for operational sharing.

This application is an operational support tool. It is not a system of record for student personal data, contracts, payments, attendance, room reservations, transport reservations, or other institutional transactions.

## 2. Access boundary

Production access uses a controlled PoC authentication boundary:

- allowed email address;
- RSJP Schedule-specific PoC password verified against a server-side scrypt hash;
- signed HttpOnly session cookie;
- eight-hour session lifetime;
- Production forced to restricted mode with no demo fallback.

Preview/local development uses demo mode for UI/UAT with a syntactically valid email plus `12345`.

Authentication protects application access. It does not create centralized schedule storage, multi-user synchronization, or an institutional audit trail.

## 3. Supported workflow

1. Authenticate.
2. Create or select a programme.
3. Set programme name, type, student count, start date, and end date.
4. Configure the default Japanese-language class pattern.
5. Apply date-specific Japanese-class overrides when needed.
6. Run automatic schedule generation.
7. Add or edit non-generated events manually.
8. Review the calendar preview.
9. Export JSON for backup and transfer.
10. Export CSV, ICS, or HTML for downstream use.

## 4. Programme types

- RSJP
- Custom

The programme type is descriptive. The current application does not enforce a separate business-rule engine by programme type.

## 5. Schedule categories

- Japanese Class
- Orientation
- Escort
- Campus Tour
- Cultural Experience
- Company Visit
- Buddy Lunch
- Completion Ceremony
- Other

## 6. Automatic generation

Automatic generation replaces only items previously generated by the automatic-generation routine for the selected programme. Manually entered events are retained.

The current generator creates first-day escort, first-day orientation, first-day campus tour, a completion ceremony template entry, and weekday Japanese-language classes subject to programme settings and date-specific overrides.

Staff must review generated entries before operational use. Generated entries are templates, not confirmed reservations.

## 7. Japanese-class configuration

Programme-level configuration supports enabled/disabled, start time, lesson duration, break duration, number of periods, number of classes, class display names, and default teacher room.

A date-specific override can change enabled/disabled, start time, lesson duration, break duration, number of periods, number of classes, classroom list, and teacher-room list.

## 8. Manual event data

Manual schedule entries can contain date, start/end times, category, Japanese and optional English title/location/notes, room-needed flag, participant/buddy/KVH counts, transport mode, bus details, pickup/drop-off, and arrangements-needed flag.

## 9. Export functions

### JSON
JSON is the application backup and transfer format. It contains the programme and schedule state used by the application. Imported state is validated before replacement.

### CSV
CSV provides a tabular schedule suitable for spreadsheet use and downstream operational processing.

### ICS
ICS provides calendar events using Asia/Tokyo as the intended time zone.

### HTML
HTML provides a printable/shareable calendar-style representation.

### Japanese / English output
The application supports Japanese and English export modes. English-specific fields should be entered when accuracy matters. The built-in fallback translation is intentionally limited and must not be treated as professional translation.

## 10. Data storage

Primary runtime storage is browser localStorage using the key `rsjp_schedule_mvp_state_v2`.

Consequences:

- data remains on the browser/profile in which it was created;
- data is not automatically synchronized between devices;
- normal authentication logout keeps the local working dataset;
- explicit delete-and-logout removes the known working dataset;
- clearing site/browser data can remove the working dataset;
- changing browsers or computers does not transfer data automatically;
- the repository and Vercel deployment do not constitute a shared schedule database.

The core ScheduleApp does not use IndexedDB and does not send the working schedule dataset to a server API. JSON export is the operational backup/transfer method.

## 11. Data classification

Do not enter unnecessary personal information into titles, locations, or notes. In particular, avoid passport data, medical data, immigration documents, personal addresses, private phone numbers, credentials, payment information, or other sensitive student information.

This application should contain operational programme-level schedule information only.

## 12. Human-control principle

The application does not confirm bookings, reserve rooms, appoint staff, place transport orders, or send schedules automatically. Staff remain responsible for checking and approving schedule information before external or institutional use.

## 13. Current limitations

- PoC email/password authentication rather than company SSO;
- no central database;
- no multi-user real-time collaboration;
- no server-side schedule audit log;
- no automatic institutional backup;
- no automatic room or transport reservation;
- no authoritative translation engine;
- no automatic conflict resolution.

These limitations are acceptable only when the application is used according to the operational rules in `OPERATIONS.md`. The intended future authentication target is company-managed SSO such as Microsoft Entra ID.
